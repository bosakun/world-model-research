# 世界を「一つの数字の塊」ではなく、物体と空間として表す

## 1. 一つのlatent vectorの限界

画像全体を一つのzへ圧縮する方法は便利です。しかし、画像にAgent、Goal、壁、複数の物体があると、それぞれの情報が一つの塊に混ざります。

    z = 「Agent、Goal、背景、関係」が混ざったメモ

予測はできても、「Goalだけ右へ動かすとどうなるか」のような操作や説明が難しくなります。

## 2. C-SWM

C-SWMは、物体ごとにstateを持ち、物体どうしの関係から次の状態を予測します。

    object Aのstate
    object Bのstate
    AとBの関係
    -> 次の各object state

物体が増減しても同じ種類のruleを使いやすい点が利点です。ただし、画像のどこが一つの物体かをどう得るかは別の問題です。

## 3. Slot Attention

Slot Attentionは、画像特徴をいくつかのslotへ集めます。

    画像特徴の集まり
    -> slot 1, slot 2, slot 3 ...

各slotが一つの物体らしいものを担当することを期待します。ただしslotに「これはGoal」と名前が最初から付くわけではありません。slotの順序が入れ替わる問題もあります。

## 4. SlotFormer

SlotFormerは、複数slotの時間変化をTransformerで予測します。各objectを別々に残しつつ、物体間の関係もattentionで扱います。

## 5. 3D Occupancy

画像だけでは、奥行きや物体の裏側が分かりにくいことがあります。occupancyは、3D空間の各場所が物で埋まっているかを表します。

    3D座標 -> 空いている / 物がある

ロボットが移動したり物を避けたりするには、画像より直接的な表現になることがあります。

## 6. まとめ

- 一つのlatent vectorは情報が混ざりやすい。
- object-centric表現は物体ごとのstateを作る。
- slotは教師なしで物体らしいまとまりを作ろうとする。
- 3D occupancyは物体が空間のどこを占めるかを表す。
- 物体らしい表現が得られることと、正しい物理予測ができることは別に評価する必要がある。
