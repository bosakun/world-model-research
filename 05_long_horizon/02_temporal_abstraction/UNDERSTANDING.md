# 時間をまとめて見るtemporal abstraction

## 何が困るのか

長い未来をprimitive action一つずつで予測すると、計算回数が増え、誤差を積み重ねる回数も増えます。

    右 -> 右 -> 右 -> 右

を一歩ずつ扱う代わりに、数stepをまとめた変化として扱う考え方がtemporal abstractionです。

## macro actionとは

例えば上の4回のactionを、

    「右へ4step進む」

という一つのmacro actionとして表します。modelは細かな途中経過ではなく、まとまりのある時間スケールで次stateを予測します。

## 何が良いのか

- 長い目的地へ向かう変化を少ない遷移で扱える。
- 予測をつなぐ回数を減らせる。
- Planningで長い行動を考えやすくなる。

## 何を失うか

途中の細かな変化を飛ばすので、障害物回避や接触のような精密制御には弱くなる場合があります。macro actionの長さを固定すると、状況によっては長すぎたり短すぎたりします。

## 自分で説明できるか

- temporal abstractionは何をまとめるか。
- 一歩ずつ予測する方法より有利になり得る理由は何か。
- 細かい制御ではどんな弱点があるか。
